측정 주체: 측정 스크립트 작성과 실행은 포트폴리오 정리 과정(2026-09-27~28)에서 AI 코딩 에이전트(Claude Code)로 했다. 조건은 실행 전에 고정했고 결과를 그대로 옮겼다. 사후 재측정이며 원하는 값이 나올 때까지 반복하지 않았다.

# 주제 1. 주문 취소와 결제 요청의 경쟁 (수정 전/후 재측정)

측정 날짜: 2026-09-28 (KST). 같은 조건의 앞선 측정은 2026-09-27-before-after.txt의 "측정 1"에 있다.
대상 커밋: 수정 = efc62e4, 수정 전 = 1527762 (efc62e4^)
환경: WSL2 (Linux 6.18) / Docker Desktop 29.7.2 / OpenJDK 21.0.12 / Testcontainers postgres:16-alpine / 단일 JVM, 같은 커넥션 풀 / StubPgClient. (Docker Desktop 29.7.2는 09-28 측정 시작 전 `docker info`로 확인한 값이다. 호스트 OpenJDK 버전은 09-28에 따로 기록하지 않았고, 같은 머신의 전날(2026-09-27) 측정 기록 값이다)
      psql 실험은 postgres:16.15-alpine 일회용 컨테이너.
한계: 운영 환경이 아니다. 같은 JVM의 2스레드를 래치로 동시에 출발시킨 테스트이며 조건당 100회다.
      "98/100"은 운영에서의 발생률이 아니라 "동시에 오면 거의 매번 뚫린다"는 뜻이다.
      조건 A에서 위반이 아닌 2회는 취소가 먼저 커밋돼 결제 준비가 ORDER_NOT_PAYABLE로 거부된 경우다.
방법: 변형마다 worktree를 만들고 측정 전용 테스트 1개(커밋하지 않음)를 넣어 실행했다.
      변형 = before(1527762) / after(efc62e4) / alt2(1527762 + "결제 쪽만 잠금" 패치).
      한 회 = 주문 1건 생성 -> 결제 요청 스레드 + 취소 스레드 -> 판정 -> outbox 소진 -> 후속 상태 기록.
      위반 = 주문이 CANCELLED이고 payments에 SUCCEEDED/REFUNDING/REFUNDED가 있음.
      조건 A: 두 스레드 래치 동시 출발, PG 승인 지연 50ms.
      조건 B: payments BEFORE INSERT 트리거로 pg_sleep(0.2)를 넣어 결제 준비 구간을 넓히고, 결제 먼저 출발, 취소는 50ms 뒤 출발, PG 지연 50ms.
      조건은 실행 전에 고정했다. 조건 A·B는 09-27(2026-09-27-before-after.txt)과 09-28에 각각 한 번씩 쟀고 두 날의 결과를 모두 공개했다. 원하는 값이 나올 때까지 반복하지 않았다.

## 2. 측정 테스트 소스 전문 (CancelPayRaceV1MeasureTest.java)

배치 위치: app/src/test/java/com/groupdrop/payment/CancelPayRaceV1MeasureTest.java
변형 이름은 `getOrDefault("MEASURE_VARIANT", "?")`의 "?"를 before/after/alt2로 치환해 넣어 실행했다.

```java
package com.groupdrop.payment;

import static org.assertj.core.api.Assertions.assertThat;

import com.groupdrop.common.ApiException;
import java.util.ArrayList;
import java.util.List;
import java.util.Map;
import java.util.TreeMap;
import java.util.concurrent.Callable;
import java.util.concurrent.CountDownLatch;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;
import java.util.concurrent.TimeUnit;
import org.junit.jupiter.api.Test;

/**
 * V1 검증관 측정 전용 (커밋하지 않음). 조건은 실행 전에 고정했다.
 * 한 회 = 주문 1건 생성 -> 결제 요청 스레드 + 취소 스레드 -> 판정 -> outbox 소진 -> 후속 상태 기록.
 * 위반 = 주문 CANCELLED 이고 payments 에 SUCCEEDED/REFUNDING/REFUNDED 가 있음.
 * 조건 A: 두 스레드 래치 동시 출발, PG 승인 지연 50ms.
 * 조건 B: payments BEFORE INSERT 트리거 pg_sleep(0.2), 결제 먼저 출발, 취소는 50ms 뒤 출발, PG 지연 50ms.
 */
class CancelPayRaceV1MeasureTest extends AbstractPaymentIntegrationTest {

    private static final int RUNS = 100;

    @Test
    void measure() throws Exception {
        String variant = System.getProperty("measure.variant", System.getenv().getOrDefault("MEASURE_VARIANT", "?"));
        run(variant, "A(natural, PG 50ms)", false);
        try {
            jdbc.execute("""
                    CREATE OR REPLACE FUNCTION measure_payments_sleep() RETURNS trigger AS $$
                    BEGIN PERFORM pg_sleep(0.2); RETURN NEW; END $$ LANGUAGE plpgsql
                    """);
            jdbc.execute("""
                    CREATE TRIGGER measure_payments_sleep_trg BEFORE INSERT ON payments
                    FOR EACH ROW EXECUTE FUNCTION measure_payments_sleep()
                    """);
            run(variant, "B(trigger pg_sleep 200ms, cancel +50ms)", true);
        } finally {
            jdbc.execute("DROP TRIGGER IF EXISTS measure_payments_sleep_trg ON payments");
            jdbc.execute("DROP FUNCTION IF EXISTS measure_payments_sleep()");
            System.out.println("MEASURE_V1 variant=" + variant + " cleanup: trigger rows="
                    + jdbc.queryForObject("SELECT count(*) FROM pg_trigger WHERE tgname='measure_payments_sleep_trg'", Long.class)
                    + " function rows="
                    + jdbc.queryForObject("SELECT count(*) FROM pg_proc WHERE proname='measure_payments_sleep'", Long.class));
        }
    }

    private void run(String variant, String condition, boolean staggered) throws Exception {
        int violations = 0;
        Map<String, Integer> pay = new TreeMap<>();
        Map<String, Integer> cancel = new TreeMap<>();
        Map<String, Integer> fin = new TreeMap<>();
        Map<String, Integer> afterDrain = new TreeMap<>();
        Map<String, Integer> pgCalls = new TreeMap<>();
        for (int i = 0; i < RUNS; i++) {
            OrderFixture order = order(10, 1);
            pgClient.reset();
            pgClient.setDuringConfirm(() -> sleep(50));

            Callable<String> payTask = () -> {
                try {
                    return "OK:" + paymentService.requestPayment(BUYER, order.orderId(), key(),
                            new CreatePaymentRequest(order.totalAmount())).body().status();
                } catch (ApiException e) {
                    return "ApiException:" + e.getCode();
                } catch (RuntimeException e) {
                    return e.getClass().getSimpleName();
                }
            };
            Callable<String> cancelTask = () -> {
                try {
                    if (staggered) {
                        sleep(50);
                    }
                    return "OK:" + orderService.cancelOrder(BUYER, order.orderId()).status();
                } catch (ApiException e) {
                    return "ApiException:" + e.getCode();
                } catch (RuntimeException e) {
                    return e.getClass().getSimpleName();
                }
            };
            List<String> results = runTogether(payTask, cancelTask);
            inc(pay, results.get(0));
            inc(cancel, results.get(1));
            inc(pgCalls, "confirmCalls=" + pgClient.confirmCount());

            String orderStatus = orderStatus(order.orderId());
            List<String> paymentStatuses = jdbc.queryForList(
                    "SELECT status FROM payments WHERE order_id=? ORDER BY id", String.class, order.orderId());
            long settled = count("payments", "order_id=" + order.orderId()
                    + " AND status IN ('SUCCEEDED','REFUNDING','REFUNDED')");
            boolean violated = "CANCELLED".equals(orderStatus) && settled > 0;
            if (violated) {
                violations++;
            }
            inc(fin, "order=" + orderStatus + " payments=" + paymentStatuses);

            while (outboxWorker.drain() > 0) {
                // 이 회차가 남긴 payment.finalized 소진 -> 주문 후속 처리 관찰
            }
            long refunds = count("refunds", "order_id=" + order.orderId());
            long skipped = count("audit_logs", "resource_type='ORDER' AND resource_id=" + order.orderId()
                    + " AND action='ORDER_TRANSITION_SKIPPED'");
            List<Integer> inv = inventoryOf(order.inventoryId());
            inc(afterDrain, "order=" + orderStatus(order.orderId()) + " refunds=" + refunds
                    + " auditSkipped=" + skipped + " inventory[init,avail,reserved,sold]=" + inv
                    + (violated ? " (violation)" : ""));
        }
        String p = "MEASURE_V1 variant=" + variant + " condition=" + condition;
        System.out.println(p + " violations=" + violations + "/" + RUNS);
        System.out.println(p + " pay=" + pay);
        System.out.println(p + " cancel=" + cancel);
        System.out.println(p + " pgConfirm=" + pgCalls);
        System.out.println(p + " final=" + fin);
        System.out.println(p + " afterOutboxDrain=" + afterDrain);
    }

    private List<String> runTogether(Callable<String> first, Callable<String> second) throws Exception {
        CountDownLatch ready = new CountDownLatch(2);
        CountDownLatch start = new CountDownLatch(1);
        try (ExecutorService executor = Executors.newFixedThreadPool(2)) {
            List<Future<String>> futures = new ArrayList<>();
            for (Callable<String> task : List.of(first, second)) {
                futures.add(executor.submit(() -> {
                    ready.countDown();
                    start.await();
                    return task.call();
                }));
            }
            assertThat(ready.await(10, TimeUnit.SECONDS)).isTrue();
            start.countDown();
            List<String> results = new ArrayList<>();
            for (Future<String> future : futures) {
                results.add(future.get(30, TimeUnit.SECONDS));
            }
            return results;
        }
    }

    private static void inc(Map<String, Integer> map, String key) {
        map.merge(key, 1, Integer::sum);
    }

    private static void sleep(long millis) {
        try {
            Thread.sleep(millis);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new IllegalStateException(e);
        }
    }
}
```

## 6. psql 2세션 실험 (원인 확인)

목적: "한 쿼리의 조건은 쿼리 시작 시점에 판정되므로, 잠금을 먼저 받고 새 쿼리로 다시 확인해야 한다"는 설명을 두 세션으로 직접 확인한다.
스크립트 주석과 E2 제목에 적힌 용어는 실험 전 가설을 부르던 이름이다. 결론은 아래 결과와 해석에서 읽는다.
컨테이너: postgres:16.15-alpine 일회용 (이름 v1-epq-pg, 실험 뒤 삭제).

### 스크립트 (psql-two-session-experiment.sh)
```bash
#!/bin/bash
P="docker exec -i v1-epq-pg psql -U postgres -X -q -v ON_ERROR_STOP=1"
reset() {
$P <<SQL
DROP TABLE IF EXISTS payments; DROP TABLE IF EXISTS orders;
CREATE TABLE orders(id int primary key, status text, updated_at timestamptz default now());
```

## 7. 재현 방법

<worktree>는 임의의 빈 디렉터리다. Docker가 실행 중이어야 한다. 변형마다 약 1분.

```bash
# 1. worktree 생성 (변형마다 하나)
git worktree add --detach <worktree>/wt-before 1527762
git worktree add --detach <worktree>/wt-after  efc62e4
git worktree add --detach <worktree>/wt-alt2   1527762

# 2. 대안 패치 적용 (alt2만). 이 파일 3절의 diff를 alt2.diff로 저장한 뒤
git -C <worktree>/wt-alt2 apply <path>/alt2.diff

# 3. 측정 테스트 복사 (이 파일 2절의 소스를 CancelPayRaceV1MeasureTest.java로 저장)
for v in before after alt2; do
  cp <path>/CancelPayRaceV1MeasureTest.java <worktree>/wt-$v/app/src/test/java/com/groupdrop/payment/
  # 변형 이름 치환 (라벨만 바뀌며 측정 결과에는 영향이 없다)
  sed -i "s/getOrDefault(\"MEASURE_VARIANT\", \"?\")/getOrDefault(\"MEASURE_VARIANT\", \"$v\")/" <worktree>/wt-$v/app/src/test/java/com/groupdrop/payment/CancelPayRaceV1MeasureTest.java
done

# 4. 실행 (변형 이름은 소스의 "?"를 before/after/alt2로 치환해 넣은 것)
cd <worktree>/wt-before/app && ./gradlew test --tests 'com.groupdrop.payment.CancelPayRaceV1MeasureTest' -i
cd <worktree>/wt-after/app  && ./gradlew test --tests 'com.groupdrop.payment.CancelPayRaceV1MeasureTest' -i
cd <worktree>/wt-alt2/app   && ./gradlew test --tests 'com.groupdrop.payment.CancelPayRaceV1MeasureTest' -i

# 5. 수정 전 코드에서 회귀 테스트 실패 확인
git show efc62e4:app/src/test/java/com/groupdrop/payment/PaymentConcurrencyTest.java > <worktree>/wt-before/app/src/test/java/com/groupdrop/payment/PaymentConcurrencyTest.java
cd <worktree>/wt-before/app && ./gradlew test --tests 'com.groupdrop.payment.PaymentConcurrencyTest.주문_취소와_결제_요청이_동시에_와도_취소된_주문에_성공_결제가_남지_않는다' -i

# 6. psql 실험: 6절 스크립트를 psql-two-session-experiment.sh로 저장하고,
#    일회용 postgres:16.15-alpine 컨테이너(이름 v1-epq-pg)를 띄운 뒤 실행
docker run -d --name v1-epq-pg -e POSTGRES_PASSWORD=x postgres:16.15-alpine
until docker exec v1-epq-pg pg_isready -U postgres; do sleep 1; done
bash psql-two-session-experiment.sh
docker rm -f v1-epq-pg
```

측정 뒤 정리: `git worktree remove --force <worktree>/wt-before` (after, alt2도 같다).

## 8. 이 측정이 말하지 않는 것

- 운영 환경의 발생 빈도. 경쟁 구간은 결제 준비 트랜잭션이 도는 짧은 시간이고, 빈도는 재지 않았다.
- 수정 전후의 처리량·지연 차이. 잠금은 주문 1행이며 PG 호출은 트랜잭션 밖이지만, 부하 비교는 하지 않았다.
- SERIALIZABLE 등 다른 격리 수준과의 비교.
